- **Study run and lakehouse additions (Python only).** `age_method` is a study decision: `run_study(age_method=)` and `reproduce_study.py --age-method` choose `"completed_years"` (both presets) or the deprecated `"year_difference"`; an explicit value overrides `cohort_params`, and `<prefix>_run.json` records the rule actually used. `export_to_delta_lake()` (new `[delta]` extra) writes a DataFrame, DuckDB relation, DuckDB table or Parquet file / directory to a Delta Lake table, with `scripts/export_delta_lake.py` as its command line; `scripts/compare_study_deltas.py` writes `<prefix>_Deltas.csv`, `<prefix>_Delta_Rows.csv` and an optional Markdown summary for two manuscript workbooks. `export_to_andromeda()` registers a `Decimal` adapter so DuckDB `DECIMAL` columns export to SQLite. - **BigQuery vs DuckDB and R vs Python parity checks** (R and Python, same rules). `run_duckdb_demo()` builds the BigQuery demo's cohort (native Circe compiler) and features (new `inst/sql/duckdb_demo_features.sql`, the DuckDB twin of the GoogleSQL template) on DuckDB; `copy_demo_sample_from_bigquery()` copies a fixed person sample and the `concept_ancestor` rows it needs; `compare_cohorts()`, `compare_features()`, `compare_column_types()`, `check_id_precision()`, `compare_demo_summaries()` and `compare_demo_outputs()` compare the results (Python: `omop_etl.backend_parity`, plus `python -m omop_etl.backend_parity compare-outputs`). Python writes the demo SQL files byte for byte as R does. **Fixed:** the demo could never run live on the public SynPUF dataset, which has no `visit_occurrence` or `measurement` table; both demos (R and Python) now create empty stand-ins in the scratch dataset (`stub_visit_occurrence`, `stub_measurement`) and say so in the report, so the cohort, demographics and type checks run while utilization reads 0.
- **Testing plan.** `testing/real-world-testing-plan.md` sets out what CI can and cannot cover for `to_sql` on a live Oracle, the DGX Spark GPU image and post-0.11.1 features on non-synthetic data, and what needs a person on those machines.

# omopduckdb 0.21.0

Fixes from the 2026-11-12 external review of 0.20.0. Most of the critical and major findings landed first in PR #59 (first bullet below); this release adds the items listed after it. Version bump 0.20.0 to 0.21.0.

- **Review fixes after the v0.20.0 review.** `parse_omop_datetime()` now converts 12-hour times (`'4:15 PM'`) to 24-hour before parsing; before, ISO dates silently dropped the AM/PM. A full-mode `etl_pcornet()` re-run empties the tables it fills in one transaction instead of doubling them. `consortium_patient_overlap()` withholds the size of any site smaller than `min_cell_count` (the self-pair row revealed the suppressed count). R gains an exported `load_vital()` matching Python: fallback standard concepts (never 0), derived BMI, `plausible_ranges`, a returned summary. Race `01`/`04` now map to American Indian or Alaska Native (8657) and Native Hawaiian or Other Pacific Islander (8557); ethnicity `NI`/`UN`/`OT` map to 0 not 'Not Hispanic'; `DX_TYPE` `10`/`SM` map to ICD10CM/SNOMED and unknown types no longer fall to ICD10CM. `run_dqd(check_levels="TABLE")` accepts a single string and rejects unknown levels; Python `load_vocabulary` loads `drug_strength`. The README worked examples use the real argument names and return shapes. `build_schema()` is re-runnable (a no-op on a complete schema, an error on a partial one), runs in a transaction, and takes `keys = TRUE` to apply primary keys and indices (DuckDB cannot apply the CDM foreign keys). Era, observation-period, `cdm_source` and `remap_all()` rebuilds are transactional; `import_omop()` and the BigQuery loader no longer leave half-emptied tables. Operator-supplied table names (`output_table`, `target_table`, `cohort_table`, export tables, attach aliases) are validated and COPY paths and options are quote-escaped. PCORnet discharge status `A` maps to 'Discharged alive' (4161979), no longer Home; the AMA feature category uses 32216; `remap_cdm_table()` prefers the custom map, then 'Maps to', then standard concepts; the DQD CONCEPT check counts ids missing from the vocabulary; the Usagi import skips unreviewed and targetless rows.
- **More review items.** Table 1 SMD is `Inf` (not 0) for perfectly separated constants (Python and R); `export_site_summary()` extra tables use complementary suppression (`group_cols=`) and are refused when they carry an unlisted count-like integer column; `parse_omop_date()`'s format list and `DEFAULT_DATETIME_FORMATS` accept `%Y%m%d`; the age features, risk scores, cohort-flow age and readmission SQL macro use completed years (see Breaking below).
- **OHDSI tool checks.** New parity scripts `scripts/ohdsi_parity_cohortmethod.R`, `ohdsi_parity_cohortconstructor.R` and `ohdsi_parity_deepplp.R` (wrapped by `tests/testthat/test-ohdsi-parity-scripts.R`, gated on `OMOP_RUN_HADES_TESTS=true`) compare CohortMethod 6.0.3, CohortConstructor 0.6.3 and DeepPatientLevelPrediction 2.4.0 with direct counts, `execute_circe_cohort()` and the labels; the omop-learn backend was run against the real omop-learn classes. ATLAS 3, Data2Evidence, Phenelope and GIS remain unchecked (see `OHDSI_INTEGRATION.md`). **Fixed:** `as_plp_data()` returned a `CovariateData` whose `$` did not dispatch under current Andromeda / FeatureExtraction.
- **Breaking: age is now computed in completed years.** `define_study_cohort()`, `build_readmission_cohort()`, `build_end_of_life_cohort()` and the age features (`extract_patient_features()`, `extract_temporal_features()`, the risk scores, the cohort-flow age, the ML age column, the readmission SQL macro) used `date_diff('year', ...)`, which counts calendar-year boundaries and so reported people born late in the year as one year older (a 17-year-old passed `min_age = 18`). The default `age_method` is now `"completed_years"`; `"year_difference"` still works to reproduce older results but warns that it is deprecated. On the randomized test CDM the RFC example drops 11 under-18 index stays (189 to 178 at the age step); the legacy-builder golden files were regenerated. Circe age criteria keep the Circe definition (year of event minus year of birth), and `extract_benchmark_features()` keeps its pipeline-equivalent calculation.
- **Documentation.** The README is now a short entry point (install, quick start, guide index, key caveats); the long walkthroughs moved to vignettes, grouped on the website (Build and operate; Cohorts and features; Clinical tools and multi-site work; Machine learning and OHDSI; Cloud and demos; Reproducibility and status). `OHDSI_INTEGRATION.md` is now the `ohdsi_integration` vignette; `NOTES.md` and `operations` moved into `status_and_roadmap` and `database_and_mapping`; the three study-feature vignettes (R, Python, across sites) are one `study_features` vignette; the portable cohort definition notes are a section of `study_cohorts_and_features`. New runnable example `inst/examples/bigquery_duckdb_roundtrip.qmd` checks the BigQuery demo and a BigQuery to DuckDB copy (offline by default). README.Rmd and README.md are in sync again.

Highlights of this development version: the cohort definitions ship with the package (`inst/cohorts`); the native Circe compiler evaluates many more constructs and accepts 521 of the 707 PhenotypeLibrary definitions (was 368), each new construct checked against the official engine; cohort reconciliation, feature ablation, run comparison, bundle concept checks and a worked end-to-end example give a downstream study tools for the questions it meets; the DQD catalog exists in R and was compared with the official DataQualityDashboard; and the intermittent Windows R crash was traced to a failed DuckDB extension load and fixed.
