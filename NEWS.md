# omopduckdb 0.35.0

The follow-ups in issue 106 (Kyle's suggestions after run C17). Version bump 0.34.2 to 0.35.0; manuscript template v0.35.0 (one Discussion sentence reads the seed sensitivity when the run has one). Items 1, 2 and 4 change model features, so the features must be extracted again.

- **Combination drugs count for every ingredient class (behaviour change).** In the standard strategy, `extract_medication_classes()` rolls `drug_concept_id` up through `concept_ancestor`, which holds valid standard concepts only. A row left on a deprecated RxNorm drug, a Brand Name or a combination product that no single ingredient could replace (`backfill_drug_concepts()` leaves those) counted for no class. With `combination_ingredients = TRUE` (the default) such a row now counts for the class of each of its valid standard RxNorm ingredients (`drug_strength` and the ingredient relationships, retired links included), of the valid standard drugs reached through brand and form links, and of its valid 'Maps to' targets. A combination product counts for every class of its ingredients. Dose-form and route exclusions still apply. `drug_exposure` is not changed. `attr(result, "combination_flags")` / `result.attrs["combination_flags"]` counts the (row, class) flags only this rule sets; `FALSE` restores the earlier behaviour. `attrs["combination_flags_by_class"]` (Python) splits the count by class, and the run record gives, per site, the share of stays that each class reached only this way (`medication_combination_share`). Python and R.
- **`backfill_condition_concepts(con)`** does for diagnoses what `backfill_drug_concepts()` does for drugs. A `condition_occurrence` row whose `condition_concept_id` is 0, non-standard or deprecated takes its source concept's 'Maps to' target (through 'Concept replaced by' when the source is deprecated), a valid standard Condition concept. The source concept is `condition_source_concept_id`, else the old concept, else the ICD-10-CM / ICD-9-CM code of `condition_source_value` looked up without its dot by the diagnosis date. A code that maps to several conditions keeps the first on its row and gets one new row for each other target (`add_rows = FALSE` keeps one). The function raises when the vocabulary has no 'Maps to' rows and returns the counts `non_standard_before`, `by_maps_to`, `rows_added`, `other_domain`, `no_target` and `non_standard_after`. Elixhauser reads ICD source codes and is not affected; phenotypes and concept-set features that read `condition_concept_id` are. Python (like `backfill_drug_concepts()`).
- **Day-0 and overlapping readmissions.** The readmission rule counts an inpatient stay that starts after the discharge day, as the legacy rule did, so a stay starting on the discharge day or inside the index stay is not a readmission. `site_quality_report.py` now always reports, as ranges across sites, the share of index stays with such a stay and their size relative to the counted readmissions (section "Readmission rule"; needs `--db-dir` and the run's `cohort_<site>.parquet`). `define_study_cohort(merge_episodes_days = 0)` is the sensitivity analysis: stays that start on or before the previous stay's end day plus `merge_episodes_days` are merged into one episode (the first stay's row, the last stay's end and discharge), and the cohort is built on the episodes. Off by default (`NULL`). Python and R.
- **UCUM unit conversions before the bounds (behaviour change).** `extract_benchmark_features(unit_conversions = "default")` converts glucose (mmol/L x 18.016) and BUN (mmol/L x 2.801) to mg/dL, creatinine (umol/L / 88.42) to mg/dL, and albumin and hemoglobin (g/L / 10) to g/dL, by `unit_concept_id` or, when that is 0, by the unit text. The conversion is applied before the physiologic bounds, so such values are no longer dropped or kept on the wrong scale. `DEFAULT_UNIT_CONVERSIONS` lists them; `unit_conversions = NULL` / `None` turns them off; `attrs["unit_converted"]` gives the converted share per lab. `site_quality_report.py` flags a lab whose per-unit medians at a site still differ by a factor of 5 or more after the conversions (section "Lab units"). Python and R.
- **`observation_period` end-date cap.** `run_study(observation_period_cap = "YYYY-MM-DD")` and `reproduce_study.py --observation-period-cap` end every observation period on that date for the run (a temporary view; the site database is not changed). A site whose extract ends with a spike of period ends near its pull date otherwise looks observed until then. The cap must fall on or after the study end plus the follow-up days. The run record gives the share of periods it shortened per site; without a cap the spike check runs as before.
- **`reproduce_study.py --sensitivity`** (`run_study(sensitivity = TRUE)`): the features are also extracted on every eligible stay, and `stay_sensitivity()` fits the HistGBM on ten random one-stay-per-patient draws (seeds 1 to 10, `--sensitivity-seeds`) and on all eligible stays with patient-grouped folds, as in the Nov 11 deliverable. It writes `<prefix>_Sensitivity.csv` (seed, stays, readmission rate, AUC-ROC, Brier) and adds the summary to the run record; template v0.35.0 cites the seed range in the Discussion. Off by default; it adds roughly the time of one feature extraction and ten model fits.
- **Expected and unexpected findings.** `run_study(known_source_gaps =)` and `reproduce_study.py --known-source-gaps` take the study team's list of confirmed source gaps (a mapping, list, JSON file or text file of `column # reason`; a key may be `site:column`). Each data-check finding now has a cause: `source_gap` (on the list), `intentional` (a concept-set exclusion), `etl_mapping` (vocabulary, concept-set coverage, transfer and address checks) or `unexplained`. A listed gap no longer stops the run. The script prints unexpected findings first, and the run record counts findings by cause. A lab's intentional concept-set exclusions (`ConceptSetExclusionWarning`) are listed once per study with the number of sites, not once per site. `site_quality_report.py --known-source-gaps` marks those measures expected and gives each lab funnel row a likely cause (no rows with its codes, rows not mapped to its concepts, no numeric value).

# omopduckdb 0.34.2

Fixes from the run C15 close-out checks and Kyle's remaining-gotchas review (2026-11-24). Version bump 0.34.1 to 0.34.2; manuscript template v0.34.2. The cohort and the features must be built again.

- **`n_secondary_dx` counts the index visit only (Kyle's choice).** When the cohort has `visit_occurrence_id`, a diagnosis dated inside the stay but recorded on another visit (an outpatient, ED or observation encounter, or another inpatient visit) no longer counts. A diagnosis with no visit id still counts by its date. In the C15 close-out, 1 to 9% of the counted codes per site sat on another visit, and the site means would fall by 0.0 to 0.8. A cohort without `visit_occurrence_id` keeps the date rule. Python and R.
- **`backfill_drug_concepts()` remaps non-standard drug concepts.** A drug row whose `drug_concept_id` is not a valid standard concept (non-standard, or deprecated / upgraded) now takes that concept's 'Maps to' target when there is exactly one valid standard target; the old concept goes into `drug_source_concept_id` when that is empty. The medication classes roll drug concepts up through `concept_ancestor`, which holds standard concepts only, so these rows were missed: 4 to 17% of drug rows per site in the C15 close-out, built by a builder that kept the source concept. Rows with no target or several are left as they are. The result has two new counts, `non_standard_before` and `by_maps_to`. The step runs before the existing concept-0 fill.
- **Stays still in hospital are excluded.** `define_study_cohort(still_in_hospital_status=)` drops index stays whose `discharged_to_source_value` is a "still in hospital" code (PCORnet DISCHARGE_STATUS `SH`); it adds the attrition step "Discharged (not still in hospital)". On in the protocol cohort (`PROTOCOL_COHORT_PARAMS`) and in `build_ederri_diabetes_cohort()`, off by default in `define_study_cohort()`. Such a stay has no discharge, so no 30-day window after it. The legacy notebooks dropped SH with IP and EX; run C10 had 456 SH stays at three sites. OMOP has no standard concept for it, so the rule reads the source value. Template v0.34.2 says so in Section 2.1.1. Python and R.
- **Tobacco is the latest status up to discharge (Kyle's choice).** The level of the latest tobacco record on or before discharge decides (a PCORnet smoking status, ICD F17 / Z72.0 / 305.1 for current, Z87.891 / V15.82 for former, a never-smoker status); records on the same day go to the higher level. Until 0.34.1 any current-use record ever made the stay "Current user", so a patient who had quit stayed current. Template v0.34.2 defines tobacco use in Section 2.2. Python and R.
- **RUCA 99 is Missing / Unknown.** USDA code 99 ("not coded": unpopulated tracts, PO-box ZIPs) is no longer counted as Small Town / Rural: `ruca_category()`, `derive_geography_features()` and `ruca_feature()` default to `code_99_missing = TRUE`; `FALSE` restores the reference coding. Python and R.
- **ZIP codes keep their leading zeros on the `location.zip` path.** The converters write a 5-digit ZIP to `location.zip` (the same rule as `person_address_history.zip5`; it was the raw ZIP9 or ZIP5, so "8101" stayed 4 digits). The geography readers (`geography.zip5_sql()`, R `.zip5_sql()`) turn a stored ZIP into its 5 digits and pad a 4-digit ZIP or an 8-digit ZIP+4; a 3-digit value is left to the ZIP3 fallback, which now also reads a ZIP3 stored as is. Before, the readers took the first run of five digits, so a 4-digit ZIP was lost. Python and R.
- **Drugs with no 'Maps to' take their single ingredient.** In the C16 audit, the drug rows still on a non-standard concept after the remap were deprecated RxNorm drugs (Branded, Clinical and Quant drugs, a few Ingredients) and valid RxNorm Brand Name concepts. The vocabulary has no 'Maps to' or valid 'Concept replaced by' row for any of them. `backfill_drug_concepts()` now gives such a row the concept's single standard RxNorm Ingredient (`by_ingredient`) and leaves a combination product as it is. The ingredient comes from the concept itself, its clinical drug, its unquantified form or its pack contents, through `drug_strength` or an ingredient relationship (`RxNorm has ing`, `Has ingredient`, `Brand name of`, `Tradename of`). Retired links count, because a deprecated concept keeps only those. A deprecated ingredient takes the standard ingredient of the same name. The medication classes roll up from ATC to ingredients, so an ingredient is enough. One caveat: an ingredient carries no route, so a topical form of a corticosteroid counts as systemic. The remap also raises an error when `concept_relationship` has no 'Maps to' row, and returns `non_standard_after`.
- **Figure 1 fits its page.** In run C17, the 12-step Figure 1 at full width pushed the last line of its caption onto the page number. A figure is now narrowed when its height at full text width would exceed 7.2 inches (`manuscript_text.figure_width()`; the 12-step flowchart prints at about 90%).
- **Two more manuscript checks.** `omop_etl.manuscript_checks` now has 10 checks. The new ones flag a collapsed bullet (".- ", the C15 slip) and any text less than 14 points above a page's number (the C17 slip).
- **Recorded differences from the legacy pipeline (pre-C16 audit).** The audit listed four rules as unrecorded or missing. Nothing in the package changes for them:
  - *Elixhauser window.* The package reads all diagnosis history up to discharge with the protocol's code lists (`profile="ederri"`). This reproduced the grant-scoped deliverable's flags at 99.99% (0.15.0). A 730-day window appears only in a legacy Table 1 script. `extract_elixhauser_comorbidities(lookback_days = 730, end_inclusive = TRUE)` reproduces that script.
  - *Sex.* The models use a binary `female` flag from `gender_concept_id` 8532, while the legacy Table 1 had a third "Other" level. No cohort patient has gender concept 0 at any site (audit A2c), so the level would be empty.
  - *BMI from ICD-10 Z68 codes.* The Nov 11 feature SQL filled a BMI category from Z68.1 to Z68.4. The package fills BMI from height and weight and from the 365 days before admission (`bmi_fill = "derive_lookback"`, 0.34.1), which leaves 1.3% missing. A Z68 code gives only a category, not a value, so it is not used.
  - *Missing discharge date.* A legacy helper used admission plus `ADMIT_DURATION` when `DISCHARGE_DATE` was empty. `ADMIT_DURATION` is not a PCORnet CDM field. The package converter uses the admission date, so such a stay has length 0 and fails the 1-day minimum. Run C17 reports how many stays this affects.

Counts below `min_cell` are blanked in subgroup tables. **Figures:** `plot_cohort_flowchart()` (Figure 1 from an attrition table), `explain_models()` (SHAP for the four benchmark models on the last cross-validation fold: exact linear SHAP for logistic regression and exact tree contributions for XGBoost, so neither needs `shap`; random forest and HistGBM use `shap.TreeExplainer` when installed), `shap_ranking()`, `plot_shap_beeswarm()` and `plot_shap_panels()` (the 2 x 2 composite); `build_study_tables(figures=True, attrition=...)` writes them. Figures are drawn with matplotlib alone. **Checked** against a study's existing grant-scoped outputs on 225,939 patients (about 10 minutes on one workstation): the performance table, the first-vs-later-stay table and the length-of-stay table were identical to the hand-built scripts' output, the tuning table had identical numbers (only the row order and the "(benchmark)" label differ), and the per-site dates matched. The leave-one-site-out table in `build_study_tables()` uses `evaluate_loso_transport()` (balanced training, prior-shift calibration), which is a different estimator from an uncalibrated pooled split, so its AUCs are close to but not identical with a hand-built script's. `random_stay_draw()` reproduces a numpy-seeded draw; `define_study_cohort(sample_stay_rule="random")` uses the MD5-based rule, and the two choose different stays. **`extract_benchmark_features()` checked against a study's own pipeline on one real site (about 63,000 stays), then fixed.** The cohort (`define_study_cohort`) reproduced the pipeline's all-stays cohort exactly (same stays, outcomes and attrition; `one_per_patient=False, sampling_rule="earliest"` gives its chronological `stay_rank`, while `sample_stay_rule="all"` ranks in stable random order). The features differed in four ways, now addressed: (1) **physiologic bounds**: single vital and lab measurements outside plausible limits are dropped before the stay mean / latest value (`bounds="default"`, `DEFAULT_BOUNDS`; `bounds={name: (min, max)}` overrides, `bounds=None` turns them off; a BMI of 562000 no longer reaches the table), and WBC reported per uL is rescaled to 10^3/uL (`DEFAULT_RESCALE`); (2) **LOINC lists**: `BENCHMARK_LAB_LOINCS` is a superset of the core panel (ALT often arrives as 1743-4 and was missed; also glucose 41653-7, HbA1c 17856-6 / 17855-8, bicarbonate 2026-3, AST 30239-8) and adds `hematocrit`, `alkaline_phosphatase`, `ldl`, a measured `anion_gap`, and the vitals `heart_rate`, `respiratory_rate`, `body_temperature`, `oxygen_saturation` (`BENCHMARK_VITAL_LOINCS`); a measured anion gap is kept and `Na - Cl - HCO3` only fills stays without one; (3) **`hematocrit_fallback`** fills a missing hemoglobin with hematocrit / 3; (4) **`profile="ederri"`** selects the protocol's medication classes (`EDERRI_MEDICATION_SPECS`: ATC A10BA, A10A, A10BB, C09, C02, C07, H02, C10), the window [discharge - `lookback_days`, discharge] (`medication_window="pre_discharge"`) the hematocrit fallback, and the protocol's Elixhauser definitions (`extract_elixhauser_comorbidities(code_table="ederri")`, the ICD-9 / ICD-10 prefix lists of the study protocol in `inst/extdata/comorbidity/elixhauser_codes_ederri.csv`, generated from the protocol's own SQL; weights and columns as in the Quan table; read over all history up to discharge, `elixhauser_lookback_days=None`; Python only). With `profile="ederri"` every vital, lab and medication column that both sides produce was identical to the pipeline's on that first site (exact agreement, including the outlier-prone BMI, WBC and AST, and ALT and hemoglobin now found). The generic medication classes and the `pre_admission` window remain the default because they are a different clinical definition, not an error. The 31 Elixhauser flags went from 92% mean agreement with the pipeline (Quan table, 365 days; the worst flag, other neuro, 59%) to 99.99% (lowest flag 99.98%): the Quan lists and the 365-day window explained the gap (all history alone only reached 96%). The residual stays differ because the pipeline matches dotted prefixes literally (`E11.9`) while the package normalises dots away, so an undotted `E119` is uncomplicated here and complicated there. **Choosing the definitions: use, don't use, or both.** `extract_benchmark_features(profile=)` takes `None` (generic definitions), `"ederri"` (the study protocol's) or `"both"` (generic columns as usual plus the protocol's Elixhauser flags and medication classes under an `ederri_` prefix, so the two can be compared side by side); each choice can also be made alone with `elixhauser_code_table` (`quan` / `ederri` / `both`), `elixhauser_lookback_days`, `medication_set` (`generic` / `ederri` / `both`), `medication_window` (new `pre_discharge`), `hematocrit_fallback` and `include_protocol_history`, and an explicit argument always wins over the profile. New `extract_protocol_history_features()` returns the protocol's history columns (`prior_encounters_all_count`, `prior_ip_os_ed_count`, `days_since_prior_encounter` (any visit), `days_since_prior_ip_ed`, `readmission_count_twelve_months`, `n_secondary_dx_ccs`, `elix_pre_index_conditions_count`, `tobacco`); on that site all eight were identical to the pipeline's. **R:** all of the above is ported to the R package (`extract_benchmark_features()`, `extract_elixhauser_comorbidities(code_table=)`, `extract_protocol_history_features()`, `BENCHMARK_LAB_LOINCS`, `BENCHMARK_VITAL_LOINCS`, `DEFAULT_BOUNDS`, `DEFAULT_RESCALE`, `EDERRI_MEDICATION_SPECS`); on that site the R and Python tables with `profile="both"` were identical in all 162 columns. **Other sites:** the cohort reproduced the pipeline's all-stays cohort exactly (same stays, outcomes, `stay_rank` and attrition) at all five sites (from about 63,000 to about 605,000 stays per site), and with `profile="ederri"` every comparable vital, lab, medication and Elixhauser column agreed (at least 99.9%, almost all exactly) at each of them, and the eight protocol history columns were identical (exact) at all five; the default (generic) definitions agreed on only 24 of about 60 columns, which is the reason the profile exists. **SDI / RUCA checked on real data.** `derive_geography_features()` and `extract_benchmark_features(include_sdoh=True)` were run on all five site databases with the study's own RUCA crosswalk, Robert Graham Center ZCTA table, fixed cut points (25, 41, 58, 77) and dated address table (`ederri_address_history`) and compared with the pipeline's geography. The address rule (in effect at admission, else latest before, else earliest after; ZIP beats no ZIP; preferred; nearest start) reproduced the pipeline exactly at two sites (ZIP, RUCA category and SDI quintile 100%) and at the other three for 64% to 99.8% of ZIPs; every one of the ZIP differences checked (all of them at two sites, a random 3,000 at the third) was an exact tie on the documented rule, two addresses with the same start date, both in effect and neither preferred, which the pipeline resolved arbitrarily. **Changed:** ties are now broken deterministically (later start, then lowest ZIP), so repeated runs and R and Python agree (R and Python gave identical ZIP, rule, RUCA and SDI for all stays at one of the sites); `extract_benchmark_features(address_table=)` (Python and R) selects the dated address table, because the default `"auto"` reads `person_address_history`, else the usually empty `person.location_id`, and returns no ZIP at all for a database that keeps its history elsewhere (it now warns when no stay has a ZIP); and `sdoh_missing` is now 1 when the SDI quintile is unknown (it was 0 for stays with no ZIP because the unknown level is the string `"SDI: Missing / Unknown"`, not NA). **Descriptive tables and the workbook.** New `table_one()` (every column overall and by outcome, median [Q1, Q3] / n (%) with Mann-Whitney or chi-square p, counts under `min_cell` shown as `<11`), `logistic_regression_table()` (unpenalised multivariable fit, odds ratios with Wald 95% CIs; flags per flag, other columns per 1 SD; composites such as the Van Walraven score are left out by `lr_drop_cols`) and `missingness_table()` (percent missing overall and per site). `build_study_tables(descriptive=True)` adds them, plus a `CONSORT_Attrition` table from `attrition`, and `extra_tables={name: DataFrame}` adds any further sheet to the CSVs and the workbook. `prepare_model_matrix()` now also drops cohort bookkeeping and outcome-derived columns (`outcome_flag`, `outcome_date`, `y`, `index_date`, ...), every date column, and any column identical to the label (with a warning): found when the first end-to-end run on a single site gave AUC 1.000 because `extract_benchmark_features()` returns a copy of the label as `y`. **End to end on one site** (random stay per patient, 2017-01-01 to 2022-09-30, 14,226 patients, 10.1% readmitted, `profile="ederri"`): cohort, 121 feature columns and all tables ran in under two minutes with 10 bootstraps, AUC-ROC 0.69 (HistGBM, XGBoost) to 0.71 (random forest, logistic regression). **Pooled five-site run with repo defaults** (random stay per patient, 2017-01-01 to 2022-09-30, `profile="ederri"`, SDI/RUCA from the study's address table, 100 bootstraps): 225,939 patients, the same total and the same per-site counts as the current grant-scoped deliverable, 10.34% readmitted (deliverable 10.00%; the package's MD5 stay draw differs from the study's numpy-seeded draw, so about 0.1% of stays differ). # omopduckdb 0.14.0

**Version 0.14.0: study-design features (`FeatureSet`), plus two fixes from the 0.13.0 audit (Python and R).** **New:** `omop_etl.study_features` / R `study_features` collect person-level features a protocol needs but OMOP does not define: `feature_set()` / `FeatureSet` extended with `add_feature()` / `.add()`; built-ins `ruca_feature()`, `sdi_feature()`, `area_feature()` (any ZIP-keyed numeric such as ACS median household income, with `none` / `log1p` / `percentile` / `zscore` transforms, a `<name>_missing` indicator and optional median imputation), `sql_feature()` and `custom_feature()`; `register_feature_factory()` and named `feature_list()`. `compute_features()` resolves the address in effect at admission once and returns one row per index stay; `write_feature_set()` stores the values as `measurement` rows under site-defined concepts (SDI and RUCA keep the `GEOGRAPHY_CONCEPT_IDS`), and `feature_set_covariate_settings()` / `feature_set_extraction_r()` give the matching OHDSI FeatureExtraction settings (checked end to end against FeatureExtraction on DuckDB). Transforms that learn from data (SDI cut points, a percentile grid, mean and sd, the imputation median) are fitted once with `fit = TRUE`, kept as feature state and shipped in a manifest (`export_feature_manifest()` / `load_feature_state()`; the JSON is shared by Python and R and was loaded across languages); without state they refuse to run, so quintiles and scales do not drift between sites. No reference data (Census, RUCA, SDI) is bundled. `stays_from_cohort()` builds the index stays from a cohort table. Three vignettes and a README section describe it. **Fixed:** `define_study_cohort(sample_stay_rule=)` accepts `"first"` and `"last"` as aliases of `"earliest"` and `"latest"`; `evaluate_loso_transport(model_type="hist_gbm")` drops columns that are NaN throughout the training set (scikit-learn failed on them, for example `sdi_quintile` in the SDoH fallback). Not changed: `[MASK]` stays at `vocab_size` as documented (the embedding needs `vocab_size + 1` rows); registering it as a special token would shift every token id and break frozen vocabularies. The other audit suggestions (time scaling for sequence models, ragged tensors, concept roll-up before `[UNK]`, small-site calibration smoothing) are not done. The R side is tested on R 4.6.1 with FeatureExtraction installed; nothing here has been run on a production database.

# omopduckdb 0.13.0

**Version 0.13.0: benchmark feature table, deep-learning datasets, frozen vocabulary and leave-one-site-out evaluation (Python and R, except where noted).** **Cohort:** `define_study_cohort(min_admit_date=, max_admit_date=)` are inclusive calendar bounds on the admission date (shorthand for `study_window`, same attrition step, so dropped patients and, with `sample_stay_rule="all"`, dropped stays are logged); `sample_stay_rule` (`"random"` = the MD5-based `stable_random` rule, `"earliest"`, `"latest"`, `"all"`) and `random_seed` name the stay-per-patient choice. Both default to `None`, so existing calls and golden results do not change (the old `sampling_rule="random"` still uses DuckDB `hash()`; the new `"random"` is MD5 and identical across DuckDB versions and sites). **Keys:** the ETL's hashed keys already use `md5_number_lower(...) & 0x7FFFFFFFFFFFFFFF` (`pcornet_id`, 63 bit) and every other surrogate key is a sequential `ROW_NUMBER`; nothing needed changing (the 53-bit `pcornet_id53` is only for R doubles and is not used by default). **Features:** `extract_benchmark_features(con, cohort_table, ...)` returns one leakage-free table: demographics, 31 Elixhauser flags anchored at discharge and including the index stay's diagnoses, 8 medication classes, index-admission vital means, lab means **and** latest in-stay values (`lab_<name>` / `lab_<name>_last`) with CKD-EPI 2021 eGFR and anion gap for both, prior IP / ED / OS utilization and prior readmissions, discharge disposition one-hots, and optional SDI quintile / RUCA category (`include_sdoh=True` needs the RUCA and SDI files and frozen cut points). No measurement dated after discharge is used (tested with a planted post-discharge value). **Deep learning:** `extract_multimodal_deep_dataset()` binds the prior-visit concept tensor to the dense covariates, label and person ids (`numpy_dict`, `torch_dict`, `memmap` = chunked `.npy` files, `arrow` = fixed-size nested list parquet; chunked output equals the in-memory result); `extract_intra_stay_tokens()` tokenizes daily lab level (L/N/H against the measurement's reference range), lab trend, drugs started and procedures between admission and discharge; `make_pretraining_targets()` adds BERT-style masked-concept labels (`[MASK]` = `vocab_size`) and next-visit flags, reproducible for a seed whatever the chunk size; `export_concept_vocabulary()` / `import_concept_vocabulary()` freeze a tokenizer in a checksummed JSON manifest so token ids match across sites. `output_format="zarr"` writes one chunked `.zarr` array per output (optional `zarr` extra, v2 and v3 API; checked on zarr 2.18 here, v3 in the Docker build). **R:** `define_study_cohort()` has the same four new arguments (and the `stable_random` rule); `extract_benchmark_features()`, `evaluate_loso_transport()` (ridge logistic model only), `fit_recalibrator()`, `platt_scaling_*`, `isotonic_*`, `adjust_for_prevalence()`, `capacity_threshold()`, `capacity_risk_tiers()`, `evaluate_at_capacity()`, `build_concept_tokenizer()`, `export_concept_vocabulary()` / `import_concept_vocabulary()` (same JSON file as Python, checked both ways) and `make_pretraining_targets()`. Not in R: the multimodal tensor dataset, intra-stay tokens and memmap / Arrow / Zarr output (R's `extract_longitudinal_tensors()` uses a different hash-based token layout), xgboost models, and Python-identical random draws (R's sampling, bootstrap and masking use R's RNG, so numbers differ for the same seed; the properties are tested). **Transport:** `evaluate_loso_transport()` trains on N-1 sites (optionally balanced 1:1), scores the held-out site at natural prevalence and reports AUROC, AUPRC, Brier, O/E, calibration slope and intercept, top-k PPV / sensitivity / lift, with 95% bootstrap intervals (`"logistic"` or `"xgboost"`); `fit_recalibrator()` / `platt_scaling_*` / `isotonic_*` / `adjust_for_prevalence()` map balanced scores to the natural rate; `capacity_threshold()`, `capacity_risk_tiers()` and `evaluate_at_capacity()` turn probabilities into "riskiest k%" tiers. The Docker image now installs the `bundle` extra (xgboost, onnxruntime) and scikit-learn (new `sklearn` extra, also in `dev`) for downstream modelling; the library itself does not import it, and `model_type="xgboost"` uses xgboost's native API. **Follow-ups from live acceptance testing on a production-format database (also in 0.13.0):** (1) `include_sdoh=True` without the RUCA / SDI inputs no longer raises: `sdoh_fallback="indicator"` (default) returns NaN `sdi_quintile` / `ruca_category` and `sdoh_missing = 1` with a warning (`"raise"` keeps the error; no national SDI cut points are bundled, because quintiles must use the training cohort's frozen cut points). (2) `evaluate_loso_transport(model_type=)` also takes `"hist_gbm"` and `"random_forest"` (scikit-learn; forests fill NaN with training medians). (3) `extract_benchmark_features(impute="median"|"mean", impute_values=)` fills vitals and labs for models that cannot take NaN; the fill values are returned in `attrs["imputation_values"]` so they can be fitted on the training sites and reused. (4) `extract_intra_stay_measurements()` returns continuous `(N, max_days, max_obs, 3)` arrays of `[time_offset, concept_idx, normalized_value]` with a mask and the normalization used (stay window only; Python). (5) The feature table is joined once instead of column by column (no pandas fragmentation warning). (6) `vocabulary_db="auto"` attaches a `central_vocabulary.duckdb` next to the connection's database file when `concept_ancestor` is unreachable (Python only; R still needs `attach_central_vocabulary()`). R also gets (1) and (3). Fixed on the way: R CMD check failed on undocumented arguments of the new R functions (several `@param` tags shared a line). All of it was tested on synthetic data only (the R side on R 4.6.1); none of it has been run on a production-size database, and the multimodal dataset has not been trained against a real model.

# omopduckdb 0.11.2

**Version 0.11.2: open items from the PR #42 field test (Python and R).** `check_observation_period_ends()` no longer requires the latest end date to hold 1% of all periods: a pile-up of 33 ends against a typical day of 1 in 219,000 periods is now flagged, so the build-date warning fires on databases where only a few dozen periods end on the build date (F1b). `cap_observation_period(dry_run = TRUE, by_end_date = TRUE)` also returns the most common end dates among the periods it would shorten (F4), and its documentation now contrasts it with `data_cutoff = "auto"`: `"auto"` caps only open-ended enrollment spans and keeps recorded ends, the cap shortens every period after the cutoff (O2). - **Field-report items (Python; the R changes are marked and untested here).** **Breaking:** (1) `build_observation_period()` and the ETL's `data_cutoff` now default to `"auto"` (latest event before today) instead of today; pass `max_date = None` / `data_cutoff = None` (CLI `--data-cutoff today`) for the old behaviour. ### Architecture & Production Hardening
